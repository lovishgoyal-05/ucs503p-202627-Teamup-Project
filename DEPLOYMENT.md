# Free Deployment Guide (Vercel + Render + Neon)

TeamUp is split into two parts:
- **Frontend (`code/frontend`)**: React + Vite SPA deployed on **Vercel** (free Hobby tier) from the repository root (`vercel.json`).
- **Backend (`code/backend`)**: Java 21 Spring Boot API deployed on **Render** (free Docker web service) connected to **Neon** (free PostgreSQL).

---

## 1. Create a Free PostgreSQL Database on Neon
1. Sign in to [Neon](https://neon.tech) and create a new project (PostgreSQL 17).
2. From the Neon dashboard, copy your connection details:
   - `DATABASE_URL`: format it as JDBC, e.g.
     `jdbc:postgresql://<your-neon-host>/<db-name>?sslmode=require`
   - `POSTGRES_USER`: your Neon role/username
   - `POSTGRES_PASSWORD`: your Neon password
   > Flyway runs migrations (`V1__initial_schema.sql`, `V2__event_applications.sql`) automatically when the backend boots.

---

## 2. Deploy the Backend on Render (Free Docker Tier)
1. Push this repository to GitHub.
2. In [Render](https://render.com), click **New + → Blueprint** (or **Web Service**) and select your GitHub repo.
   - If using **Blueprint**, Render reads `render.yaml` automatically (`rootDir: code/backend`, `runtime: docker`, `plan: free`, `healthCheckPath: /api/v1/health`).
3. Set the required environment variables in Render:
   - `DATABASE_URL`: `jdbc:postgresql://<your-neon-host>/<db-name>?sslmode=require`
   - `POSTGRES_USER`: Neon username
   - `POSTGRES_PASSWORD`: Neon password
   - `GOOGLE_CLIENT_ID`: from Google Cloud Console
   - `GOOGLE_CLIENT_SECRET`: from Google Cloud Console
   - `ADMIN_PASSCODE`: a strong secret passcode for `/admin/login`
   - `JWT_SECRET`: auto-generated by `render.yaml` (or any 32+ character random string)
   - `FRONTEND_ORIGIN`: `https://<your-vercel-app>.vercel.app` (update once Vercel gives your URL)
   - `ALLOWED_ORIGINS`: `https://<your-vercel-app>.vercel.app` (comma-separated if you add custom domains)
   - `COOKIE_SECURE`: `true`
   - `COOKIE_SAMESITE`: `Lax` (use `None` only if you remove Vercel rewrites and set `VITE_API_URL` directly)
4. Deploy and copy your Render URL, e.g. `https://teamup-api.onrender.com`.
   - Verify health at `https://<your-render-service>.onrender.com/api/v1/health`.

---

## 3. Point `vercel.json` to Your Render Backend & Deploy on Vercel
1. Open `vercel.json` at the repository root and replace all 3 occurrences of:
   `https://REPLACE_WITH_YOUR_RENDER_SERVICE.onrender.com`
   with your actual Render service URL (no trailing slash), then commit and push.
2. In [Vercel](https://vercel.com), click **Add New… → Project**, import your GitHub repo, and keep **Root Directory** as `.` (repository root).
   - `vercel.json` automatically installs and builds `code/frontend`, outputs `code/frontend/dist`, proxies `/api/*`, `/oauth2/*`, and `/login/oauth2/*` to Render, and serves `/index.html` for React Router paths.
   - No `VITE_API_URL` environment variable is needed when using the Vercel proxy rewrites.
3. Deploy and copy your Vercel URL (e.g. `https://teamup.vercel.app`).
4. Go back to **Render → Environment** and set `FRONTEND_ORIGIN` and `ALLOWED_ORIGINS` to your exact Vercel URL (`https://teamup.vercel.app`), then redeploy/restart Render if needed.

---

## 4. Configure Google OAuth Redirect URI
In **Google Cloud Console → APIs & Services → Credentials → OAuth 2.0 Client ID**:
- **Authorized JavaScript origins**:
  - `https://<your-vercel-app>.vercel.app`
- **Authorized redirect URIs**:
  - `https://<your-vercel-app>.vercel.app/login/oauth2/code/google`
  *(Because Vercel proxies `/login/oauth2/*` and forwards `X-Forwarded-Host` / `X-Forwarded-Proto` headers, Spring Security uses your Vercel domain as the OAuth callback URL.)*

---

## Notes on Free-Tier Cold Starts
- Render's free tier spins down after 15 minutes of inactivity; the first request after idle takes ~30–60 seconds to wake up.
- You can optionally use a free uptime monitor (e.g., UptimeRobot) to ping `https://<your-render-service>.onrender.com/api/v1/health` every 10–14 minutes if you want it warm during demos.
